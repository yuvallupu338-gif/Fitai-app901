## 5.1 סקירה: ארכיטקטורה היברידית

DailySpark **לא** מייצר תוכן חופשי בזמן אמת לכל משתמש. זו טעות יקרה, איטית ומסוכנת מבחינת איכות.
במקום זאת — ארכיטקטורה בת ארבע שכבות:

```
┌─────────────────────────────────────────────────────────────┐
│  שכבה 0 · ספריית ניצוצות (Offline, Batch)                  │
│  8,000+ ניצוצות שנוצרו ונבדקו מראש · embeddings · תגיות     │
│  נוצר ב-Claude Opus 5 + עריכה אנושית · מתעדכן שבועית        │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  שכבה 1 · Retrieval — אחזור מועמדים                        │
│  pgvector ANN + מסננים קשיחים → 60 מועמדים                 │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  שכבה 2 · Ranking — דירוג הקשרי                            │
│  Contextual Bandit (Thompson Sampling) + MMR → מועמד יחיד   │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  שכבה 3 · Framing — ניסוח אישי (LLM, Haiku 4.5)            │
│  שומר על גרעין הפעולה · מתאים טון, אורך, הקשר              │
└───────────────────────────┬─────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────────┐
│  שכבה 4 · Safety & QA Gate → מסירה                          │
└─────────────────────────────────────────────────────────────┘
```

**למה היברידי:**

| איכות ועקביות | משתנה | גבוהה | גבוהה |

## 5.3 וקטור הפרופיל (User State Vector)

מיוצג כ‑**384 מימדים**, מורכב משלושה חלקים:

```
u = [ u_taxonomy (128) ‖ u_behavior (192) ‖ u_context (64) ]
```

| חלק | תוכן | עדכון |
|-----|------|-------|
| `u_taxonomy` | ממוצע משוקלל של embeddings של מטרות + תחומים + הרגלים | בכל שינוי פרופיל |
| `u_behavior` | EMA (חצי‑חיים 21 יום) של embeddings של ניצוצות שבוצעו, פחות אלה שנדחו | אחרי כל משוב |
| `u_context` | one‑hot + סקלרים: שעה, יום, אנרגיה, מצב, עומס יומן, שינה | בכל בקשה |

### נוסחת עדכון ההתנהגות
```
u_behavior ← (1 − α) · u_behavior + α · Σ(r_i · e_i) / Σ|r_i|

α = 0.18   (קצב למידה)
r_i = תגמול הניצוץ i         e_i = embedding של הניצוץ i
```

**Cold Start:** משתמש חדש מקבל `u_behavior` של הצנטרואיד של הסגמנט שלו
(k‑means על 12 פרסונות זרע), עם שונות גבוהה מלאכותית שמאלצת exploration בשבוע הראשון.

## 5.4 שכבה 1 — Retrieval

```sql
-- מועמדים: קרבה סמנטית + מסננים קשיחים
SELECT s.id, s.embedding <=> $user_vector AS distance
FROM sparks s
WHERE s.status = 'approved'
  AND s.locale = $locale
  AND s.time_budget <= $max_budget
  AND s.energy_level <= $user_energy
  AND NOT (s.topics && $blocked_topics)        -- נושאים חסומים
  AND s.id NOT IN (SELECT spark_id FROM user_sparks
                   WHERE user_id = $uid AND delivered_at > now() - interval '365 days')
  AND NOT EXISTS (                              -- דמיון סמנטי לאחרונים
        SELECT 1 FROM user_sparks us JOIN sparks s2 ON s2.id = us.spark_id
        WHERE us.user_id = $uid AND us.delivered_at > now() - interval '90 days'
          AND (s.embedding <=> s2.embedding) < 0.14)
ORDER BY distance
LIMIT 60;
```

**מסננים קשיחים (לא ניתנים לעקיפה ע"י הדירוג):**
נושאים חסומים · תקציב זמן · רמת אנרגיה · שער בטיחות מצב רגשי · שפה · נגישות (למשל: ניצוץ תנועה למשתמש שסימן מגבלה).

## 5.5 שכבה 2 — Ranking (Contextual Bandit)

**האלגוריתם:** Thompson Sampling מעל רגרסיה לוגיסטית בייסיאנית לכל משתמש
(מודל קל, ניתן לעדכון אונליין, מטפל היטב ב‑exploration/exploitation).

```
לכל מועמד c:
  x_c   = [ u ⊗ φ(c) ]                       ← מאפייני אינטראקציה
  θ̃    ~ N(μ_u, Σ_u)                        ← דגימה מהפוסטריור של המשתמש
  p̂_c  = σ(θ̃ᵀ x_c)                          ← הסתברות תגמול משוערת

  score(c) = p̂_c
           + λ_n · novelty(c)                 λ_n = 0.15
           + λ_g · goal_alignment(c)          λ_g = 0.25
           + λ_h · habit_support(c)           λ_h = 0.20
           − λ_f · semantic_fatigue(c)        λ_f = 0.30
           − λ_r · global_overexposure(c)     λ_r = 0.10
```

לאחר מכן **MMR** לגיוון על פני חלון של 14 יום:
```
final(c) = score(c) − β · max_{d ∈ last_14} cos(e_c, e_d)     β = 0.35
```

**עדכון פוסטריור** (Laplace approximation, אונליין):
```
Σ_u⁻¹ ← Σ_u⁻¹ + p̂(1−p̂)·x xᵀ
μ_u   ← μ_u + Σ_u · x · (r − p̂)
```

**מדוע Bandit ולא Deep Learning:**
1. עובד מיום 1 עם מעט נתונים.
2. Exploration מובנה — קריטי כשהמטרה היא גילוי מה עובד עבור המשתמש.
3. ניתן להסבר — מאפשר את פיצ'ר "למה קיבלת את זה".
4. עלות אימון אפסית, עדכון אונליין.
5. שכבת DL (two‑tower retrieval) תיכנס ב‑v2 **מעל** הבנדיט, כשיהיו > 5M אינטראקציות.

## 5.6 שכבה 3 — ניסוח אישי (LLM Framing)

**מודל:** `claude-haiku-4-5-20251001` (מהיר וזול, מספיק לניסוח מחדש)
**מודל לגיבוי/איכות גבוהה:** `claude-sonnet-5` למשתמשי Pro ולניצוצות generative.
**יצירת ספרייה בבאץ':** `claude-opus-5`.

### מבנה הפרומפט (System — מטמון prompt caching)


## 5.7 שכבה 0 — ייצור ספריית התוכן (Batch)

**תהליך שבועי:**
1. **ניתוח פערים** — אילו צירים בטקסונומיה (קטגוריה × מידה × טון × מצב) דלילים או שחוקים.
2. **ייצור** — Claude Opus 5, 50 ניצוצות לבקשה, עם few‑shot של הפריטים בעלי הביצועים הטובים ביותר.
3. **ביקורת אוטומטית** — LLM‑as‑judge בציר כפול (ראה 5.9) + בדיקת כפילות סמנטית מול הספרייה.
4. **ביקורת אנושית** — 100% בשלושת החודשים הראשונים; אחר כך דגימה של 20% + 100% לפריטים בקטגוריות רגישות.
5. **הטמעה** — יצירת embedding, תיוג, כניסה כ‑`status='approved'`.
6. **A/B בהדרגה** — פריטים חדשים מקבלים 5% תעבורה ראשונית; מקודמים לפי ביצועים.

**יעד ספרייה:** 800 בהשקה → 3,000 בחודש 3 → 8,000+ בשנה 1 (עברית ואנגלית).

## 5.8 שכבה 4 — שער בטיחות ואיכות

כל ניצוץ עובר **לפני מסירה**:

| בדיקה | שיטה | פעולה בכשל |
|-------|------|-------------|
| אורך ומבנה | ולידציית סכמה | ניסוח מחדש (עד 2 ניסיונות) → נפילה לבסיס |
| טענות רפואיות/נפשיות | מסווג + רשימת ביטויים | חסימה |
| דימוי גוף / דיאטה | מסווג | חסימה אם לא ב‑opt‑in |
| שפת סיכון | מסווג | חסימה + הפעלת M4 |
| קלישאתיות | חיפוש n‑gram מול מאגר קלישאות + ציון LLM | ניסוח מחדש |
| ביצועיות | ציון LLM ≥ 4/5 | ניסוח מחדש |
| התאמת טון | ציון LLM ≥ 3.5/5 | ניסוח מחדש |
| כפילות | דמיון קוסינוס < 0.86 מול 90 יום | מועמד הבא |

**Fallback סופי:** אם הכל נכשל — ניצוץ evergreen מאומת מרשימת 50 פריטים שנבדקו ידנית.
**המשתמש לעולם לא רואה שגיאה או מסך ריק.**

## 5.9 הערכה ומדידה

### הערכה לא‑מקוונת (Offline)
**LLM‑as‑judge** על סט זהב של 300 ניצוצות, מדורג ב‑5 צירים (1–5):
`ביצועיות · ספציפיות · חדשנות (אנטי‑קלישאה) · התאמת טון · בטיחות`

- שני שופטים עצמאיים (מודלים/פרומפטים שונים); פער > 1.5 → הכרעה אנושית.
- סף שחרור לפרודקשן: ממוצע משוקלל ≥ 4.2, בטיחות ≥ 4.8, אף ציר < 3.5.

### הערכה מקוונת (Online)
| ניסוי | מדד ראשי | גודל מדגם מינימלי | משך |
|-------|----------|--------------------|------|
| שכבת ניסוח מול בסיס | Spark Completion Rate | 4,000 משתמשים | 14 יום |
| כיול Bandit (λ) | WAS | 6,000 | 21 יום |
| מודל זמן שליחה | Open Rate + Completion | 8,000 | 14 יום |
| טון ברירת מחדל | D7 Retention | 10,000 | 30 יום |

**Guardrails בכל ניסוי:** notification opt‑out, uninstall, "לא בשבילי" rate, דיווחי תוכן.
עצירה אוטומטית אם guardrail חורג ב‑> 20% יחסית.

## 5.10 פרטיות בעיצוב

| עיקרון | יישום |
|--------|-------|
| **מזעור נתונים** | ל‑LLM נשלח **סיכום פרופיל נגזר**, לא היסטוריה גולמית ולא PII |
| **פסאודונימיזציה** | מזהה משתמש בבקשות ה‑AI הוא hash מסובב (rotating), לא ה‑user_id |
| **הערות אישיות** | מוצפנות; **אינן** נשלחות למודל אלא אם המשתמש הפעיל "תובנות מהערות" |
| **ללא אימון** | תוכן משתמש אינו משמש לאימון מודלים; מוגדר חוזית מול הספק |
| **שמירת נתונים** | אינטראקציות גולמיות 24 חודשים → אגרגציה; יומני LLM 30 יום |
| **On‑device** | צ'ק‑אין רגשי, נתוני יומן ובריאות מעובדים למאפיינים **במכשיר**; רק המאפיין הנגזר עולה |
| **זכויות** | יצוא ומחיקה מלאים מתוך האפליקציה, ללא פנייה לתמיכה |
