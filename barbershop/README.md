# רון מלכה · ברברשופ

אתר תדמית ומערכת הזמנת תורים למספרה, בעברית ובכיוון ימין־לשמאל.
שני עמודים: `index.html` ללקוחות ו־`admin.html` ליומן של רון.

אתר סטטי לגמרי — HTML, CSS ומודולי JavaScript. **בלי npm install ובלי אף תלות.**

יש שתי דרכים להריץ אותו, ושתיהן עובדות:

| | |
| --- | --- |
| **התיקייה** | `index.html` + `admin.html` + הנכסים. דורש שרת (או GitHub Pages). זו הגרסה שעורכים. |
| **קובץ אחד** | `dist/ron-malka-barbershop.html` — כל האתר, כל התמונות וכל הגופנים בקובץ HTML יחיד. לוחצים עליו פעמיים והוא נפתח. בלי שרת, בלי אינטרנט, בלי תיקיות. |

---

## קובץ אחד שאפשר פשוט לפתוח

```bash
node tools/build-single.mjs
# → dist/ron-malka-barbershop.html   (כ-2.4MB)
```

הקובץ הזה הוא האתר **וגם** היומן. אין בו עמודים — יש hash:

* `ron-malka-barbershop.html` → האתר
* `ron-malka-barbershop.html#admin` → מסך הנעילה של רון (יש קישור "כניסת מנהל" בפוטר)

מה שנבדק ועובד מ־`file://` (כלומר בלחיצה כפולה, בלי שרת): התמונות, הגופנים
העבריים, הזמנת תור מלאה, שמירה ב־localStorage, **וגם בדיקת הסיסמה** — Web Crypto
זמין ב־`file://` כי הדפדפן מחשיב אותו הקשר מאובטח.

הבנייה קוראת את `index.html` ואת `admin.html` ומרכיבה מהם את הקובץ, כך שאין עותק
שלישי של הקוד שצריך לתחזק. אם מוסיפים קישור לעמוד שלישי — הבנייה **נעצרת** עם
שגיאה, במקום לייצר קובץ עם הפניה מתה.

> הערה על אבטחה: ב־GitHub Pages העמודים מוגשים עם `script-src 'self'`. בקובץ
> היחיד הסקריפט והעיצוב הם inline, אז הם ננעלים לפי **sha256** — לא ב־`unsafe-inline`,
> שהיה פותח בדיוק את החור שהאתר המוגש סגור מפניו.

## הפעלה מקומית (גרסת התיקייה)

```bash
cd barbershop
python3 -m http.server 8000
# ואז לפתוח http://localhost:8000
```

חייבים שרת ולא לפתוח את הקובץ ישירות (`file://`), משתי סיבות: מודולי JavaScript
דורשים origin אמיתי, ובדיקת הסיסמה משתמשת ב־Web Crypto שזמין רק בהקשר מאובטח —
כלומר `https` או `localhost`.

הנכסים כבר בריפו. אם תרצה להוריד אותם מחדש או להחליף תמונה:

```bash
node tools/fetch-assets.mjs          # מדלג על מה שכבר קיים
node tools/fetch-assets.mjs --force  # מוריד הכל מחדש
```

## ⚠️ מה המערכת הזאת כן ולא עושה

שני דברים שחייבים להיות ברורים לפני שמסתמכים עליה. שניהם נובעים מהבחירה באתר
סטטי עם אחסון בדפדפן — לא מבאג, ולא ממשהו שאפשר לתקן בקוד.

### 1. התורים נשמרים בדפדפן שבו נקבעו

הנתונים יושבים ב־`localStorage`. תור שלקוח קובע מהטלפון שלו נשמר **בטלפון שלו**,
ולא יופיע ביומן של רון. אין שרת שיעביר אותו.

לכן המערכת בנויה סביב שני גשרים שהופכים אותה לשימושית בפועל:

* אחרי אישור תור נפתחת ללקוח **הודעת וואטסאפ מוכנה** לרון עם כל הפרטים. זה מה
  שמעביר את ההזמנה בפועל.
* ביומן יש **הזנת תור ידנית**, וגם **ייצוא וייבוא** של גיבוי — כך שרון מנהל יומן
  אמיתי אצלו, ומזין לתוכו את מה שמגיע בוואטסאפ.

המספר שההודעות נשלחות אליו נמצא ב־`src/js/config.js` ומוגדר לזה של רון. אם הוא
משתנה, צריך לעדכן את שתי השורות יחד — אחת היא הכתובת שוואטסאפ מקבל והשנייה היא
מה שהמבקר קורא:

```js
phoneE164: '972526564130',    // ← 05X-XXXXXXX הופך ל-9725XXXXXXXX
phoneDisplay: '052-656-4130',
```

`node tools/smoke.mjs` נכשל אם המספר חוזר להיות פלייסהולדר.

### 2. הסיסמה של המנהל מגנה מפני סקרן, לא מפני תוקף

באתר סטטי אין שרת, אז בדיקת הסיסמה רצה בדפדפן של המבקר. מה שכן ומה שלא:

| | |
| --- | --- |
| ✅ | הסיסמה **לא נמצאת** בריפו. יש בו רק PBKDF2-SHA256 שלה, עם salt ו־310,000 סיבובים. קריאה בקוד המקור לא תחשוף אותה, וניחוש offline יקר. |
| ✅ | מי שנכנס ל־`admin.html` בלי הסיסמה רואה מסך נעילה וזהו. |
| ✅ | חמישה ניסיונות שגויים נועלים לדקה. |
| ❌ | מי שפותח DevTools יכול לעקוף את הבדיקה לגמרי. שום קוד שרץ בצד לקוח לא יכול למנוע את זה. |
| ❌ | התורים עצמם לא מוצפנים — הם ב־`localStorage` של הדפדפן. |

**המסקנה:** זה מספיק כדי שלקוח סקרן לא יסתובב ביומן. זה לא מספיק מול מישהו
שמנסה. הגנה אמיתית מחייבת שהבדיקה תרוץ על שרת.

**להחלפת הסיסמה:**

```bash
node tools/set-password.mjs
```

הכלי מבקש סיסמה בלי להדפיס אותה, מגריל salt חדש, ומעדכן את שלושת הקבועים
ב־`src/js/auth.js`. הסיסמה עצמה לא נכתבת לשום קובץ ולא נשמרת בהיסטוריית הפקודות.

## מה יש בעמוד הלקוחות

Hero, מחירון, גלריית תספורות עם לייטבוקס (ניווט בחצים, יציאה ב־Esc), "על המספרה",
שעות פתיחה והגעה — ובאמצע זרימת ההזמנה בארבעה שלבים:

**שירות → יום → שעה → שם וטלפון.**

* מוצגים רק ימים שבהם **השירות שנבחר** עוד נכנס. תספורת של 45 דקות תסתיר יום
  שבו נשארו רק חלונות של חצי שעה.
* השעות מחושבות משעות הפתיחה פחות תורים קיימים, פחות חסימות, פחות זמן ההתראה
  (שעה קדימה כברירת מחדל).
* בסיום: סיכום, קובץ `.ics` ליומן (עם תזכורת שעתיים לפני), וההודעה לוואטסאפ.

## מה יש ביומן של רון (`admin.html`)

**יומן** — לוח חודשי. כל יום מראה כמה תורים יש בו, אם הוא חסום ידנית ואם הוא סגור
לפי שעות הפתיחה. לחיצה על יום פותחת מתחתיו את סדר היום שלו.

**רשימת תורים** — היום / קרובים / עברו / הכל, עם חיפוש לפי שם, טלפון או שירות.
לכל תור: אישור, סימון כבוצע, ביטול, עריכה, מחיקה, חיוג והודעת תזכורת בוואטסאפ.

**חסימות** — שלוש דרכים להוריד זמן מהלוח:

| | |
| --- | --- |
| **יום שלם** | חופשה, מילואים, יום מחלה |
| **טווח שעות** | הפסקת צהריים, סידור באמצע היום |
| **קבוע בשבוע** | ימים נבחרים בשבוע — לשבוע, לשבועיים, ל‑3 שבועות, לחודש או לחודשיים קדימה |

חסימה חוזרת נשמרת כרשומה לכל תאריך תחת מזהה קבוצה אחד, ומופיעה ברשימה כשורה אחת
שאפשר לבטל בלחיצה. אם יש כבר תורים בתוך הטווח שנחסם — תופיע אזהרה עם המספר שלהם,
כי חסימה מונעת הזמנות חדשות אבל **לא** מבטלת תורים קיימים.

**סטטיסטיקות** — תורים היום, בשבוע הקרוב, הכנסה צפויה, והשירות המבוקש ביותר.

**גיבוי** — ייצוא CSV לאקסל (עם BOM, כדי שהעברית תיפתח נכון), גיבוי JSON מלא,
ושחזור מגיבוי. השחזור **מוסיף** ולא דורס, כך שאפשר לאחד יומנים משני מכשירים.

## בדיקות

```bash
node tools/smoke.mjs                              # בדיקות מבנה
RMB_PASSWORD='...' node tools/smoke.mjs           # כולל בדיקת דליפת סיסמה
```

הבדיקות מוודאות שכל נכס שמוזכר קיים על הדיסק, ש־Content-Security-Policy קיימת
ואוסרת `unsafe-inline`, שאין `innerHTML` ואין `eval` בשום מודול, שהמספר בקונפיג
הוחלף — וכשמעבירים סיסמה, **שהיא לא מופיעה באף קובץ בריפו** ושה־hash השמור אכן
מתאים לה.

## עלייה לאוויר (GitHub Pages)

תיקיית `barbershop/` עומדת בפני עצמה — אפשר להעתיק אותה לריפו נפרד ולפרסם משורש
הריפו, או לפרסם את הריפו הנוכחי ואז הכתובת תהיה `.../barbershop/`.

ב־Settings → Pages, לבחור את הענף ואת התיקייה `/ (root)`. יש בריפו `.nojekyll`
כדי ש־Jekyll לא ינסה לעבד את הקבצים.

**Pages חינמי עובד רק בריפו ציבורי** — כלומר הקוד יהיה גלוי לכולם. זו בדיוק הסיבה
שהסיסמה שמורה כ־hash ולא בטקסט גלוי.

### למה כך

**בלי כלי בנייה.** GitHub Pages מגיש קבצים סטטיים, ותיקיית המקור רצה כמו שהיא.
`build-single.mjs` הוא סקריפט Node אחד בלי אף תלות — הוא מייצר נוחות (קובץ אחד
להעביר), לא דרישה: אף אחד לא חייב להריץ אותו כדי שהאתר יעבוד.

**בלי innerHTML.** כל צומת נבנה דרך `el()` ב־`ui.js`, וטקסט של משתמש נכנס תמיד
כ־`textContent`. לקוח בשם `<script>` נשאר שם. ה־CSP הקשיחה בשני העמודים היא
השכבה השנייה, לא הראשונה.

**`connect-src 'none'`.** האתר לא מדבר עם אף שרת, אז המדיניות אוסרת זאת מפורשות.
התמונות והגופנים מאוחסנים כאן ולא נטענים מ־CDN, כך שהאתר עובד גם בלי גישה לרשת
חיצונית ולא מדליף למי שמארח אותם מי גלש בו.

**`store.js` כשכבה נפרדת.** כל קריאה וכתיבה עוברות דרכו. מעבר לשרת אמיתי הוא
כתיבה מחדש של קובץ אחד, בלי לגעת ביומן, בזרימת ההזמנה או בעיצוב.
